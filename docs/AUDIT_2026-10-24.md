# Audit — 2026-10-24

Scope: the whole repository (`server.ts`, `src/`, `test/`, `scripts/`, config, dependencies), then the platform built
and run in a container. Every finding below is marked **verified** (reproduced against the running container) or
**by reading** (traced in code, not executed). Nothing here has been fixed except F9, which is a config-only change.

## Findings

| ID | Severity | Finding | Status |
| -- | -------- | ------- | ------ |
| F1 | High | **The approval gate and ledger can be forged by any client.** `POST /api/warehouse/:collection` is unauthenticated and accepts any record. A forged `artefact_versions` row `{status:"APPROVED", approvedBy:"nobody"}` was accepted, and `/api/connector/publish` then passed the "human-APPROVED" check; it was refused only by `OPS_ALLOW_ECOSYSTEM_WRITES=false`. With writes enabled, anyone who can reach the port can open issues in the ecosystem repo attributed to a human approver. The ledger is a plain unkeyed SHA-256 chain, so a writer can also recompute a forged chain. Already tracked as OPQ-002; this confirms it is exploitable, not theoretical. | verified |
| F2 | High | **The only access control cannot be used.** `OPS_API_TOKEN` works server-side (401 without header, 200 with), but the UI never sends `x-ops-token`: `store.tsx` calls `new ServerAdapter()` with no token, and `/api/health`, `/api/connector/*`, and `remoteEngine` add no header. Setting the token makes `/api/health` 401, so the UI silently drops to browser storage. | verified (API) / by reading (UI) |
| F3 | Medium | **Signed webhook with a non-object body crashes the process.** A correctly signed `null` body reaches `summariseEvent`, throws `TypeError` inside an async Express 4 handler (not caught), and Node exits 1. Needs the webhook secret, so it is a robustness bug rather than an open door, but the handler also lacks a `try/catch` around `JSON.parse`. | verified |
| F4 | Medium | **`/api/gateway/complete` (was `/gemini`) is open by default and only pattern-checks.** Without a token anyone can spend the Anthropic key. It runs `detectPii`/`detectInjection` but does not require the `deidentified: true` provenance stamp that the in-browser gateway enforces, so the server path is weaker than the client path. | by reading (no key to exercise it) |
| F5 | Medium | **Erasure tombstones are not persisted.** `Platform.tombstone()` only adds to an in-memory `Set`: no warehouse record, no ledger entry, and nothing in the UI calls it. After a reload every "erased" subject is processable again, which contradicts "erasure is a tombstone". The Brain's own `forget()` is persisted; this subject-level gate is not. | by reading |
| F6 | Medium | **Unbounded writes.** Any collection name matching `[a-z0-9_]{1,64}` can be created and appended to without limit (2 MB per record), and every `/api/warehouse` and publish call re-reads and re-parses every file. Disk-fill and slow-down risk once F1/F2 are open. | by reading |
| F7 | Low | `OPS_API_TOKEN` is compared with `!==` (not constant-time), unlike the webhook HMAC compare. | by reading |
| F8 | Low | **Dependencies.** `npm audit`: 5 moderate/critical, but both criticals (`vitest`, `tinypool`) are dev-only and absent from the runtime image. Production: `exceljs → uuid` moderate (suggested fix is a downgrade to exceljs 3.4.0; not recommended). Two lockfiles (`bun.lock`, `package-lock.json`) can drift; `vite` is listed in both `dependencies` and `devDependencies`; build-only packages in `dependencies` make the runtime image 621 MB. | verified |
| F9 | Low | **`.env.example` is not safe for `docker --env-file`.** Inline comments become part of the value: `OPS_API_TOKEN` became a junk non-empty string (every API call would 401). Compose's own parser handles them, so compose was never affected. Writes stay off only because the code compares to the exact string `"true"`. | verified, **fixed** (comments moved to their own lines) |
| F10 | Low | `npm run dev` runs plain `vite --host=0.0.0.0` (no API server, all interfaces) while the README says it serves server + UI on 127.0.0.1. The real entry point is `npm run server`. | by reading |
| F11 | Info | The live GitHub connector is still unverified. From the sandbox it got 403/429 (no token, shared egress IP), so the result says nothing about the connector itself. | verified (inconclusive) |

## Checked and sound

* Collection names are validated; `..%2f..%2fetc` returned 400 (path traversal not possible).
* Webhook HMAC is constant-time and rejects an empty secret; unsigned requests got 401.
* HTML export escapes every text field; no `innerHTML`/`eval` sinks in `src/` (one `document.write` of already-escaped export HTML).
* CSV export neutralises spreadsheet formula injection.
* Gate order (tombstone → purpose → lawful basis), second-approver rule, claim sourcing and PII/learner refusal are exercised by the 85 tests.
* Publish checks the artefact in the *server's* copy of the warehouse (the right idea; undermined only by F1).

## Suggested order of work

1. F1 + F2 together: real sign-in (OPQ-002), server-side append validation (reject `artefact_versions` rows the client could not have produced, derive `approvedBy` from the session), and make the UI send the credential.
2. F3: wrap the webhook handler and parse in `try/catch`, require an object payload.
3. F5: persist tombstones as warehouse + ledger records and reload them in `Platform.init()`.
4. F4/F6: put the gateway behind the same auth, require provenance server-side, add per-collection quotas.
5. F8: move build-only packages to `devDependencies`, pick one lockfile, plan the vitest 5 upgrade.

## Running it in a container

```bash
docker build --target test .                 # lint + 85 tests inside the build; fails the build on any failure
docker compose up -d --build                 # http://127.0.0.1:3000 (loopback only)
docker compose down -v                       # stop and delete the data volume
```

Behind a TLS-inspecting proxy, pass its CA as a build secret (never written to a layer):
`docker build --secret id=extra_ca,src=/path/to/ca.crt …`. To let the running container trust it too, mount it and set
`NODE_EXTRA_CA_CERTS`.

Secrets come only from a gitignored `.env`. The compose file deliberately does not forward the host environment: the
first version did, and it silently copied this session's `GITHUB_TOKEN` into the container (found via
`/api/health` reporting `githubToken: true`, then removed).
